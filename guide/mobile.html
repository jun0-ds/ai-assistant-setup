첫 요청을 받은 에이전트가 읽어요. 현재 상태에 맞는 단계부터 진행하고, 필요한 로그인·기기 조작을 함께해요.

6. 휴대폰 연결〔선택〕

입력

자료 범위 이유
로컬·원격 연결 선택한 방식 localhost를 유지하며 원격으로 연결해요.
state/setup-status.md 로컬 주소·구동 방식 성공했던 로컬 연결을 기준으로 삼아요.

진행

  1. 이미 모바일 선택을 알면 그대로 진행해요. 필요 없으면 건너뛰어요. 원하는 기기에 공식 Paseo 앱을 설치해요.
  2. Tailscale 경로는 PC·다른 기기를 같은 tailnet에 로그인해요. 공유/정책이 필요한 환경은 기존 허용 범위를 확인하고 임의로 넓히지 않아요.
  3. 실제 로컬 포트·기존 Serve 설정·접근 정책을 읽어요. TCP 전달 절차로 localhost를 유지해요.
  4. 관리자 조작·네트워크 설정 변경 전 대상·포트·접근 범위·기존 설정 영향을 설명해요. 이미 승인된 범위는 반복 승인으로 막지 않아요. 전체 Serve reset이나 config 초기화는 하지 않아요.
  5. 다른 기기의 Direct connection에는 PC의 Tailnet IP와 전달 포트를, PC 자신의 앱에는 기존 localhost 호스트를 사용해요. 폰의 localhost는 PC가 아니에요.
  6. 실제 다른 기기에서 에이전트 응답과 작업 파일 접근을 확인해요. 같은 PC에서 Tailnet IP를 열어본 결과는 원격 실사용 증거가 아니에요.
  7. PC localhost에서도 다시 실제 응답을 받아요. Tailscale이 끊겨도 로컬 경로가 유지되는지 확인해요.
  8. 전원·절전·데몬·Tailscale의 유지 조건을 안내해요. 재부팅 후 확인한 범위와 아직 사용자 확인이 필요한 것을 구분해요.

출력

로컬/원격 주소·포트, 기존 Serve 보존·추가 규칙·되돌림, 실제 원격 응답과 localhost 재검사를 기록해요.

다른 기기에 접근할 수 없으면 담당 기기와 확인 행동을 적고 원격은 미확인으로 남겨요. 7. 첫 작업으로 이어가요.
