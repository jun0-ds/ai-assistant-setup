작업공간과 파일 관리

작업공간은 에이전트와 함께 일할 폴더예요. Windows의 실제 문서 폴더 아래 AgentWorkspace를 기본 위치로 제안해요. 기존 작업 위치가 있으면 사용자와 정한 경로를 써요. 문턱 소스는 준비 폴더의 source/, 개인 데이터는 작업공간의 .munteok/에 있어요. 공개 소스와 사용자 자료를 함께 Git에 올리지 않아요.

AgentWorkspace/
├── AGENTS.md                 # 공통 진입 지침
├── CLAUDE.md                 # Claude가 AGENTS를 읽는 연결
├── CONTEXT.md                # 현재 범위와 작업을 고르는 인덱스
├── .munteok/                 # 정체성·메모리·노트·도구·로컬 상태
├── 업무/
│   ├── CONTEXT.md
│   ├── 회사A/
│   │   ├── 서비스개편/
│   │   └── 보관/20261019_월간보고/
│   └── 보관/
└── 개인/
    ├── CONTEXT.md
    ├── 여행준비/
    └── 보관/20261019_컴퓨터문제해결/

회사·프로젝트 폴더는 필요한 때 만들어요. 위 이름은 예시예요. 작업공간을 폴더로 나누는 것은 파일 접근 권한을 차단하는 보안 sandbox와는 달라요.

공통 정보와 작업 문맥

호칭·협업 방식은 공통 core에 두고 회사 지식·개인 자료는 해당 범위에 둬요. 에이전트는 공통 진입 → 작업공간 인덱스 → 선택한 프로젝트 CONTEXT → 필요한 자료 순서로 읽어요. 보관 자료와 다른 회사·개인 프로젝트는 요청에 관련될 때만 찾아요.

문턱 core는 로컬 기억·노트·라우팅을 준비해요. 보부상의 기기 동기화와 사랑채 UI는 기본 설치하지 않아요. 검증 규율은 손맛, 자료 검색 방법론은 더듬이의 원천을 연결하고 그 내용을 여러 전역 파일에 복제하지 않아요.

새 일을 시작할 때

기존 프로젝트의 이어지는 일이면 해당 폴더를 사용해요. 새 일이면 업무/회사 또는 개인 아래 프로젝트·이슈 폴더를 만들고 CONTEXT.md에 목적·상태·읽을 입력·진행·출력 위치를 적어요. 상위 인덱스에 경로와 읽는 조건을 연결해요. 모든 하위 폴더에 CONTEXT를 남발할 필요는 없어요.

자료·결과·임시 폴더는 그 작업 안에 필요할 때 만들어요. 코드 저장소도 하나의 프로젝트이고 여행 준비나 월간 보고도 하나의 프로젝트예요. 일반 문서 작업에 Git 초기화를 강제하지 않아요.

끝난 일을 정리할 때

  1. 결과를 실제로 열어 확인해요. 편집 원본·최종 결과·다시 작업하는 데 필요한 코드와 자료는 남겨요.
  2. 에이전트가 만든 불필요한 임시 파일만 정리해요. 사용자의 원본이나 용도 불명 파일은 임의로 지우지 않아요.
  3. 완료 이슈와 운영 중인 서비스·진행 중 프로젝트를 구분해요. 실행 경로·링크·Git worktree·미커밋 변경이 걸리면 실제 영향부터 확인해요.
  4. 이동 전 원래 경로, 최종 결과, 손맛/대화 기록의 기존 위치를 완료 요약에 남겨요. 손맛 로그는 절대경로 기반이라 새 경로에서 자동 연결된다고 가정하지 않아요.
  5. 회사 일이면 회사 안, 개인 일이면 개인 안의 보관/YYYYMMDD_이름/으로 옮겨요. 날짜는 보관하는 날을 써요. 상위 프로젝트가 진행 중이면 완료한 이슈만 정리해요.
  6. 활성 목록과 링크를 갱신하고 보관 결과를 다시 찾아봐요. 보관을 평소 문맥에 전부 읽히지 않아요.

완료되지 않은 일을 정리했다는 이유로 완료 처리하지 않아요. 로컬 상태와 결과 경로를 남겨 다음 대화에서 이어가요.
