# 6. 휴대폰 연결〔선택〕

## 입력

| 자료 | 범위 | 이유 |
|---|---|---|
| [로컬·원격 연결](../../references/paseo-network.md) | 선택한 방식 | localhost를 유지한 채 원격 연결 |
| `state/setup-status.md` | 로컬 주소·구동 방식 | 성공한 로컬 연결을 기준으로 삼기 |

## 진행

1. 사용자가 모바일 사용 여부를 이미 밝혔다면 그대로 진행합니다. 필요 없으면 건너뜁니다. 쓰려는 기기에 공식 Paseo 앱을 설치합니다.
2. 기본은 [QR 연결](../../references/paseo-network.md#qr로-연결하기)입니다. Tailscale 설치·포트 개방·네트워크 설정이 필요 없습니다. 사용자가 원하거나 이미 쓰고 있을 때만 [Tailscale 연결](../../references/paseo-network.md#tailscale로-연결하기)을 씁니다.
3. 릴레이를 켜기 전에 무엇을 하는지 설명합니다. QR을 스캔한 기기는 이 PC의 에이전트를 쓸 수 있게 되므로 QR은 비밀번호처럼 다룹니다. QR은 사용자가 PC 앱에서 직접 띄우고 휴대폰으로 스캔합니다. QR 사진이나 페어링 링크를 채팅으로 받지 않습니다.
4. 실제 다른 기기에서 에이전트 응답과 작업 파일 접근을 확인합니다. 같은 PC에서 열어 본 결과는 원격 실사용의 증거가 아닙니다.
5. PC의 localhost에서도 다시 실제 응답을 받습니다.
6. 전원·절전·데몬·인터넷 등 연결을 유지하는 조건을 안내합니다. 재부팅 뒤 확인한 범위와 아직 사용자가 확인해야 하는 것을 구분합니다.

Tailscale을 고르면 참고 문서의 절차에 따라 localhost 연결을 유지합니다. 관리자 조작이나 네트워크 설정을 바꾸기 전에는 대상·포트·접근 범위·기존 설정에 미치는 영향을 설명하고, Serve 전체 reset이나 config 초기화는 하지 않습니다. 다른 기기에는 PC의 Tailnet IP와 전달 포트를, PC 자신의 앱에는 기존 localhost 호스트를 씁니다. 휴대폰의 localhost는 PC가 아닙니다.

## 출력

연결 방식(QR·릴레이 또는 Tailscale), 실제 원격 응답, localhost 재검사 결과를 기록합니다. QR과 페어링 링크는 기록하지 않습니다. Tailscale을 썼다면 주소·포트, 기존 Serve 보존 여부, 추가한 규칙과 되돌리는 방법도 적습니다.

다른 기기에 접근할 수 없으면 맡을 기기와 확인할 행동을 적고 원격 항목은 미확인으로 남깁니다. 그다음 [7. 첫 작업](../05-first-task/CONTEXT.md)으로 이어 갑니다.
