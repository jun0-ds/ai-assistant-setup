# 작업공간과 파일 관리

작업공간은 에이전트와 함께 일할 폴더입니다. 처음 만들 때는 C 드라이브 바로 아래의 `C:\AgentWorkspace`를 기본 위치로 씁니다. 문서 폴더는 OneDrive 동기화나 한글·공백 경로가 섞이기 쉬워서 피합니다. 기존 작업 위치가 있으면 사용자와 정한 경로를 씁니다. 문턱 소스는 준비 폴더의 `source/`에, 개인 데이터는 작업공간의 `.munteok/`에 있습니다. 공개 소스와 사용자 자료를 함께 Git에 올리지 않습니다.

```text
C:\AgentWorkspace\
├── AGENTS.md                 # 공통 진입 지침
├── CLAUDE.md                 # Claude가 AGENTS를 읽게 하는 연결
├── CONTEXT.md                # 현재 범위와 작업을 고르는 인덱스
├── .munteok/                 # 정체성·메모리·노트·도구·로컬 상태
├── 업무/
│   ├── CONTEXT.md
│   ├── 회사A/
│   │   ├── 서비스개편/
│   │   └── 보관/20261019_월간보고/
│   └── 보관/
└── 개인/
    ├── CONTEXT.md
    ├── 여행준비/
    └── 보관/20261019_컴퓨터문제해결/
```

회사·프로젝트 폴더는 필요할 때 만들며, 위 이름은 예시입니다. 작업공간을 폴더로 나눈다고 파일 접근이 막히지는 않습니다. 폴더 구분은 보안 sandbox와 다릅니다.

## 공통 정보와 작업 문맥

호칭·협업 방식은 공통 core에 두고, 회사 지식과 개인 자료는 해당 범위에 둡니다. 에이전트는 공통 진입 지침 → 작업공간 인덱스 → 선택한 프로젝트의 CONTEXT → 필요한 자료 순서로 읽습니다. 보관 자료와 다른 회사·개인 프로젝트는 요청과 관련될 때만 찾아봅니다.

문턱 core는 로컬 기억·노트·라우팅을 준비합니다. 보부상의 기기 간 동기화와 사랑채 UI는 기본으로 설치하지 않습니다. 검증 규율은 손맛의, 자료 검색 방법론은 더듬이의 원천에 연결하며, 그 내용을 여러 전역 파일에 복제하지 않습니다.

## 새 일을 시작할 때

기존 프로젝트에서 이어지는 일이면 해당 폴더를 씁니다. 새 일이면 업무/회사 또는 개인 아래에 프로젝트·이슈 폴더를 만들고, `CONTEXT.md`에 목적·상태·읽을 입력·진행·출력 위치를 적습니다. 상위 인덱스에는 그 경로와 언제 읽을지를 연결합니다. 모든 하위 폴더에 CONTEXT를 만들 필요는 없습니다.

자료·결과·임시 폴더는 그 작업 안에 필요할 때 만듭니다. 코드 저장소도, 여행 준비나 월간 보고도 각각 하나의 프로젝트입니다. 일반 문서 작업에 Git 초기화를 강요하지 않습니다.

## 끝난 일을 정리할 때

1. 결과를 실제로 열어 확인합니다. 편집 원본·최종 결과·다시 작업할 때 필요한 코드와 자료는 남깁니다.
2. 에이전트가 만든 불필요한 임시 파일만 정리합니다. 사용자의 원본이나 용도를 알 수 없는 파일은 임의로 지우지 않습니다.
3. 완료한 이슈와 운영 중인 서비스·진행 중인 프로젝트를 구분합니다. 실행 경로·링크·Git worktree·커밋하지 않은 변경이 얽혀 있으면 실제 영향부터 확인합니다.
4. 옮기기 전에 원래 경로, 최종 결과, 손맛·대화 기록의 기존 위치를 완료 요약에 남깁니다. 손맛 로그는 절대경로를 기준으로 하므로 새 경로에서 자동으로 연결된다고 가정하지 않습니다.
5. 회사 일은 회사 폴더 안, 개인 일은 개인 폴더 안의 `보관/YYYYMMDD_이름/`으로 옮깁니다. 날짜는 보관하는 날짜를 씁니다. 상위 프로젝트가 진행 중이면 완료한 이슈만 정리합니다.
6. 활성 목록과 링크를 갱신하고 보관한 결과를 다시 찾아봅니다. 보관 자료를 평소 문맥에 모두 읽히지는 않습니다.

정리를 했다고 끝나지 않은 일을 완료로 처리하지 않습니다. 로컬 상태와 결과 경로를 남겨 다음 대화에서 이어 갑니다.
