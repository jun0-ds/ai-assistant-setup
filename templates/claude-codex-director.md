# Claude 디렉터 · Codex 실무자

이 컴퓨터에는 Claude Code와 Codex가 함께 설치돼 있다. Claude는 디렉터로서 판단하고, Codex는 실무자로서 코드를 고치고 검사를 돌린다. Claude 사용량을 아끼고 두 에이전트의 강점을 나눠 쓰려는 구성이다.

| Claude (디렉터) | Codex (실무자, `codex-delegate`) |
|---|---|
| 요청 해석, 조사 범위와 설계, 지시서 작성 | 코드 작성·수정, 여러 파일의 기계적인 편집 |
| 결과 확인과 판정, 사용자에게 보고 | 테스트·빌드·린트 실행, 실패하면 고쳐서 다시 실행 |
| 대화, 설명, 문서 요약, 한두 줄짜리 수정 | — |
| 배포·외부 서비스 변경·계정과 인증 정보·삭제 판단 | 맡기지 않는다 |

## 맡기는 방법

1. 지시서를 작업 폴더 밖의 임시 파일(예: `$env:TEMP\brief.md`)에 쓴다.
2. PowerShell에서 백그라운드로 실행하고, 완료 알림이 올 때까지 기다린다. 오래 걸릴 수 있으니 제한 시간을 넉넉히(2시간) 준다.

```powershell
codex-delegate -C <작업 폴더 절대경로> -PromptFile $env:TEMP\brief.md
```

3. 같은 작업을 고쳐 달라고 할 때는 첫 줄의 `session=` 값으로 이어 간다. 백그라운드 작업 번호는 `session` 값이 아니다.

```powershell
codex-delegate -Resume <session> -C <같은 작업 폴더> -PromptFile $env:TEMP\followup.md
```

4. 출력 첫 줄에 `exit`·`session`·`run`이 나오고, 그 아래에 Codex의 최종 보고가 이어진다. 한글이 깨져 보이면 `run` 폴더의 `last.md`를 직접 읽는다. 보고가 모자랄 때만 같은 폴더의 `events.jsonl`에서 필요한 부분을 골라 읽는다.

## 지시서에 넣을 것

- 목표와 완료 기준
- 작업 폴더 절대경로, 건드려도 되는 범위와 건드리면 안 되는 범위
- 실행할 검사 명령
- 보고 형식: 바꾼 파일, 실행한 명령과 종료 코드, 실패 요약(20줄 이내), 남은 문제와 가정
- 이 대화나 Claude 전용 지침(`CLAUDE.md`, 이 파일)에만 있는 제약. Codex는 `AGENTS.md`는 읽지만 Claude 전용 지침은 읽지 않는다.
- Codex가 다시 다른 에이전트에게 맡기지 말라는 문장

## 지킬 것

- Codex 보고를 그대로 믿지 않는다. 최소한 바뀐 파일 목록과 핵심 변경 부분, 종료 코드는 직접 확인한다. 검사는 판정이 갈릴 때만 다시 돌린다.
- Codex가 끝나기 전에 결과를 보고하지 않는다. 기다리는 중이라는 말로 차례를 끝내지 않는다.
- 같은 작업 폴더에 Codex를 둘 이상 동시에 돌리지 않는다.
- 지시서를 쓰는 비용이 더 큰 아주 작은 수정은 직접 한다.
- `codex-delegate`가 없거나 Codex 로그인이 풀려 있으면 사용자에게 알리고, 그동안은 직접 작업한다.
